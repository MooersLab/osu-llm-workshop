Lesson 3: Scripting Basics

Writing reusable Python scripts for PyMOL

Learning Objectives

  • Create and run .py script files

  • Use loops and conditionals for batch operations
  • Handle command-line arguments
  • Structure scripts for reusability

Running Python Scripts

From the command line (headless)

# Run script and exit
pymol -c script.py

# Run script, stay interactive
pymol script.py

# Run with arguments
pymol -c script.py -- arg1 arg2

From inside PyMOL

# At PyMOL prompt
run script.py

# Or from Python
exec(open("script.py").read())

Tip: Use pymol -cq script.py for fully headless batch processing (no GUI, quiet, quit after).

Check Your Understanding

What's the difference between running pymol -c script.py and pymol script.py?

Answer: pymol -c script.py runs headless (no GUI), executes the script, and exits. pymol script.py launches the GUI, runs the script, and stays interactive. Use -c for batch/automation; without -c for development/debugging.

Misconceptions: "-c means 'continue' and keeps the GUI open." "Both behave identically." "You can't use -c with scripts that need user input."

Your First Script

Save as hello_pymol.py:

#!/usr/bin/env python3
"""
hello_pymol.py — Minimal PyMOL script
Run with: pymol -c hello_pymol.py
"""

from pymol import cmd

def main():
    print("Loading ubiquitin...")
    cmd.fetch("1ubq", "ubq")
    
    print("Setting up cartoon representation...")
    cmd.cartoon("ubq")
    cmd.color("green", "ubq")
    
    print("Saving image...")
    cmd.png("ubiquitin.png", width=800, height=600, dpi=150, ray=1)
    
    print("Done!")

if __name__ == "__main__":
    main()

Run it:

pymol -c hello_pymol.py

Script Structure Template

#!/usr/bin/env python3
"""
script_name.py — One-line description

Longer description of what this script does,
its inputs, outputs, and any requirements.

Usage:
    pymol -c script_name.py [options]
"""

from pymol import cmd
import sys
import argparse

# ---- Configuration / Constants ----
DEFAULT_COLOR = "cyan"
DEFAULT_WIDTH = 800

# ---- Helper Functions ----
def setup_scene(obj_name, color=DEFAULT_COLOR):
    """Apply standard visualization to an object."""
    cmd.cartoon(obj_name)
    cmd.color(color, obj_name)
    cmd.bg_color("white")

def save_figure(filename, width=DEFAULT_WIDTH, height=600, ray=True):
    """Render and save a publication-quality PNG."""
    cmd.png(filename, width=width, height=height, dpi=150, ray=1 if ray else 0)

# ---- Main Workflow ----
def main(pdb_id, output="output.png", color=DEFAULT_COLOR):
    """Main pipeline: fetch, style, render."""
    obj = pdb_id.lower()
    
    print(f"Fetching {pdb_id}...")
    cmd.fetch(pdb_id, obj)
    
    print("Styling...")
    setup_scene(obj, color)
    
    print(f"Rendering to {output}...")
    save_figure(output)
    
    print("Complete.")

# ---- CLI Entry Point ----
if __name__ == "__main__":
    parser = argparse.ArgumentParser(description="Render a PDB structure")
    parser.add_argument("pdb_id", help="PDB ID to fetch (e.g., 1ubq)")
    parser.add_argument("-o", "--output", default="output.png", help="Output filename")
    parser.add_argument("-c", "--color", default=DEFAULT_COLOR, help="Cartoon color")
    args = parser.parse_args()
    
    main(args.pdb_id, args.output, args.color)

Check Your Understanding

In a PyMOL script, why wrap the main logic in if __name__ == "__main__":?

Answer: It allows the script to be imported as a module (e.g., for testing helper functions) without executing the main workflow. Only runs when the file is executed directly.

Misconceptions: "It's required for PyMOL scripts to work." "It makes the script run faster." "It enables command-line arguments."

Functions for Reusable Workflows

Encapsulate common patterns into functions:

def load_and_style(pdb_id, obj_name=None, style="cartoon", color="spectrum"):
    """Load a structure and apply a standard style."""
    if obj_name is None:
        obj_name = pdb_id.lower()
    cmd.fetch(pdb_id, obj_name)
    
    if style == "cartoon":
        cmd.cartoon(obj_name)
    elif style == "sticks":
        cmd.show("sticks", obj_name)
    
    if color == "spectrum":
        cmd.spectrum("b", "rainbow", obj_name)
    else:
        cmd.color(color, obj_name)
    
    return obj_name

# Use it
load_and_style("1ubq", color="green")
load_and_style("2ubq", color="blue")

Loops for Batch Operations

Process multiple structures

pdb_list = ["1ubq", "2ubq", "3ubq", "4ubq"]

for pdb in pdb_list:
    obj = pdb.lower()
    cmd.fetch(pdb, obj)
    cmd.cartoon(obj)
    cmd.util.cbc(obj)  # color by chain
    
    # Save each
    cmd.png(f"{obj}.png", width=600, height=600, ray=1)
    
    # Clean up for next iteration
    cmd.delete(obj)

print(f"Processed {len(pdb_list)} structures")

Iterate over states in a trajectory

cmd.load("trajectory.xtc", "protein", state=0)
n_states = cmd.count_states("protein")

for state in range(1, n_states + 1):
    cmd.frame(state)
    cmd.png(f"frame_{state:04d}.png", width=800, height=600, ray=1)

Check Your Understanding

When iterating over trajectory frames with for state in range(1, n_states + 1):, why does the range start at 1?

Answer: PyMOL states are 1-indexed. State 1 is the first frame. cmd.count_states() returns the total count, so the last state is n_states, requiring range(1, n_states + 1).

Misconceptions: "Python is 0-indexed so PyMOL must be too." "State 0 is the first frame." "The +1 is a bug."

Conditionals and Logic


def analyze_structure(obj):
    """Analyze and report on a structure."""
    n_atoms = cmd.count_atoms(obj)
    n_residues = len(set(cmd.get_model(obj).get_residues()))
    
    print(f"{obj}: {n_atoms} atoms, {n_residues} residues")
    
    if n_atoms > 50000:
        print("  ⚠ Large structure — consider simplifying")
        cmd.show("cartoon", obj)
    else:
        cmd.show("sticks", obj)
    
    # Check for ligands
    ligands = cmd.select("ligands", f"{obj} and hetero and not solvent")
    if ligands > 0:
        print(f"  Found {ligands} ligand atoms")
        cmd.show("sticks", "ligands")
        cmd.color("yellow", "ligands")
    
    return {"atoms": n_atoms, "residues": n_residues, "has_ligands": ligands > 0}

results = analyze_structure("my_protein")

Error Handling


from pymol import CmdException

def safe_fetch(pdb_id, obj_name):
    """Fetch with graceful error handling."""
    try:
        cmd.fetch(pdb_id, obj_name)
        return True
    except CmdException as e:
        print(f"Failed to fetch {pdb_id}: {e}")
        return False

def safe_load(filepath, obj_name):
    """Load local file with validation."""
    import os
    if not os.path.exists(filepath):
        print(f"File not found: {filepath}")
        return False
    try:
        cmd.load(filepath, obj_name)
        return True
    except CmdException as e:
        print(f"Failed to load {filepath}: {e}")
        return False

Settings and Persistence

Control PyMOL settings programmatically:


# Get/set individual settings
cmd.get("ray_shadows")        # returns current value (0 or 1)
cmd.set("ray_shadows", 0)     # disable shadows for faster rendering

# Common rendering settings
cmd.set("ray_opaque_background", 0)  # transparent background
cmd.set("antialias", 2)              # 2x antialiasing
cmd.set("ray_trace_mode", 1)         # cartoon-like ray trace

# Save/restore settings
settings_backup = {}
for key in ["ray_shadows", "antialias", "ray_trace_mode"]:
    settings_backup[key] = cmd.get(key)

# ... do rendering ...

for key, val in settings_backup.items():
    cmd.set(key, val)

Check Your Understanding

What does cmd.get_view() return and why is it useful?

Answer: An 18-element list (a 4x4 view matrix plus clipping planes) representing the exact camera position, orientation, and zoom. Saving/restoring it ensures identical views across sessions or figures.

Misconceptions: "It returns a simple (x, y, z) tuple." "It only works in the GUI, not headless." "orient() and get_view() do the same thing."

Debugging Tips

Debugging: PyMOL scripts run in a constrained environment. Tips:
  • Use print() liberally — output appears in the terminal
  • Run with pymol script.py (not -c) to keep GUI for inspection
  • cmd.refresh() forces GUI update during long scripts
  • Wrap risky code in try/except CmdException

Summary

  • Scripts: pymol -c script.py (batch) or run script.py (interactive)
  • Structure: imports → constants → helpers → main() → CLI parsing
  • Functions encapsulate reusable workflows
  • Loops enable batch processing of structures/states
  • argparse makes scripts configurable
  • Always handle CmdException for robustness
